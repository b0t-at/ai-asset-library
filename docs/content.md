# Content & voice

b0t builds tools for people who know what they are doing. Write like a competent colleague leaving a note — specific, brief, and friendly without performing friendliness.

## Voice

| We are | We are not |
| --- | --- |
| direct — "Manifest published." | hedging — "Your manifest may have been published successfully!" |
| specific — "3 installers, sha256 verified" | vague — "Everything looks good" |
| calm — "Pipeline failed at validate-manifest." | dramatic — "Oops! Something went terribly wrong 😱" |
| plain — "Delete" | cute — "Yeet it" |
| helpful — "Version needs three segments, e.g. 0.84.1" | blaming — "Invalid input" |

## Rules

1. **Sentence case** everywhere: headings, buttons, labels, menu items, tabs. "Create manifest", not "Create Manifest".
2. **No exclamation marks** in UI. One is permitted in a genuine celebration (first successful run), never in errors.
3. **No emoji** in UI text, headings, buttons or commit messages generated by tools. Icons are Lucide, not emoji.
4. **Verbs on buttons**, nouns on badges and tabs. "Publish", "Re-run pipeline" / "Merged", "Artifacts".
5. **Say what happens**, then why, then what to do. Errors: "Installer hash changed. The vendor re-uploaded the binary. Re-verify before merging."
6. **Numbers are digits**, with thousands separators: "1,284 manifests". Units have a space: "12 KB", "14 min".
7. **Time**: relative for < 24h ("14 min ago"), absolute otherwise ("4 Sep 2026, 15:02"), always with a full timestamp on hover/`<time>`.
8. **Identifiers verbatim** in monospace: `Microsoft.PowerToys`, `#48213`, `e053d6e`. Don't paraphrase them.
9. **No marketing filler**: "supercharge", "seamless", "powerful", "next-gen", "AI-powered", "effortless", "unleash", "elevate", "robust". Describe the concrete capability instead.
10. **Avoid the AI cadence**: no "Whether you're X or Y…", no tricolons of adjectives, no "In today's fast-paced world", no closing "Happy coding!". Start with the noun or the verb.

## Patterns

**Page description** (under the h1): one sentence, what this page lets you do. "Manifests b0t is tracking, with their last known version and update status."

**Empty state**: title says what's missing, body says how to fill it, button does it.
> No manifests yet — Add a package identifier and b0t will track new releases for you. [Add package]

**Destructive confirmation**: title is a question with the count, primary button repeats the verb.
> Close 3 pull requests? — They will be closed on winget-pkgs without merging. You can reopen them later. [Cancel] [Close pull requests]

**Success toast**: past tense, object, optional link. "Manifest published · View PR"

**Form hint**: constraint in plain words, example if the format is non-obvious. "Must match the winget-pkgs manifest path."

## Language

Product UI is in **English** by default (org-wide, mixed-language contributors). German projects may be German throughout — never mix within a screen. Write in a way that survives translation: short sentences, no idioms, no puns in buttons.

## README & docs voice

Same rules. First paragraph says what the tool does and for whom. Then how to run it. Badges: at most build status and version. No hero images, no emoji section headers, no "✨ Features" lists — a plain bullet list is fine.
